# Requirements Document

## Introduction

The Smart AI Image Editor is a web platform that allows users to describe image edits in plain, casual language. The platform intelligently researches the user's intent, asks targeted clarifying questions, enhances the prompt into a technically rich AI image prompt, shows the enhanced prompt for review, and then generates high-quality images — all without requiring users to understand AI prompting techniques. The system also preserves style continuity across iterative edits and supports inpainting for targeted area modifications.

## Glossary

- **Platform**: The Smart AI Image Editor web application built with Next.js and deployed on Vercel.
- **User**: A person interacting with the Platform to create or edit images.
- **Casual_Prompt**: The raw, plain-language description of an image edit submitted by the User.
- **Intent_Analyzer**: The subsystem that researches subject matter, context, artistic style references, and relevant technical knowledge from the Casual_Prompt before enhancement.
- **Prompt_Enhancer**: The subsystem powered by the Groq API (Llama 3.3 70B) that rewrites the Casual_Prompt into a rich, detailed, technically correct AI image prompt.
- **Enhanced_Prompt**: The detailed, technically correct AI image prompt produced by the Prompt_Enhancer.
- **Clarification_Engine**: The subsystem that generates 2–3 targeted clarifying questions to resolve ambiguities in the Casual_Prompt before enhancement.
- **Prompt_Review_Step**: The mandatory UI step where the User views, edits, or approves the Enhanced_Prompt before image generation begins.
- **Image_Generator**: The subsystem that calls Cloudflare Workers AI (FLUX.1-schnell or FLUX.1-dev models) to generate images.
- **Style_DNA**: A structured metadata object capturing the visual style characteristics (color palette, artistic style, tone, texture references) of a generated image, stored alongside every image in the Edit_History.
- **Edit_History**: The per-session ordered log of all images generated by the User, each entry containing the image reference, its Enhanced_Prompt, and its Style_DNA.
- **Inpainting_Tool**: The browser-based brush/selection tool that allows the User to mark a specific region of an existing image for targeted editing.
- **Inpaint_Mask**: The binary mask produced by the Inpainting_Tool that identifies the pixel region to be modified.
- **Reference_Input**: An image file or document uploaded by the User to guide the style or content of the edit.
- **Session**: A single browser session that maintains the User's Edit_History and current working state without requiring persistent authentication.
- **Image_Store**: Cloudflare R2 storage used to persist generated images and their associated metadata.
- **API_Routes**: Next.js server-side API route handlers that orchestrate LLM calls, image generation calls, and storage operations.

## Requirements

### Requirement 1: Casual Prompt Intake

**User Story:** As a User, I want to describe my desired image edit in plain, everyday language, so that I do not need to learn AI prompting syntax to get good results.

#### Acceptance Criteria

1. THE Platform SHALL provide a text input field that accepts free-form natural language descriptions of up to 2,000 characters; WHEN the character count reaches 2,000, THE Platform SHALL block further input and display a remaining-character counter to the User.
2. THE Platform SHALL accept one or more Reference_Input files (images in JPEG, PNG, or WebP format, or documents in PDF or TXT format) alongside the Casual_Prompt, up to a maximum of 5 files per submission.
3. WHEN a Reference_Input image file is attached, THE Platform SHALL display a thumbnail preview at a minimum resolution of 80×80 pixels; WHEN a Reference_Input document file is attached, THE Platform SHALL display the file name and file type.
4. IF a Reference_Input file exceeds 10 MB, THEN THE Platform SHALL display an error message that states the 10 MB limit and the size of the rejected file, and SHALL reject the upload without affecting other already-attached files.
5. IF a Reference_Input file is in an unsupported format, THEN THE Platform SHALL display an error message listing the supported formats (JPEG, PNG, WebP, PDF, TXT) and reject the upload without affecting other already-attached files.
6. THE Platform SHALL preserve the Casual_Prompt text and all attached Reference_Inputs in the Session state until the User explicitly clicks a "Clear" or "Start Over" control; WHEN that control is activated, THE Platform SHALL remove all current prompt text and Reference_Inputs from the Session state.

### Requirement 2: Intent Analysis

**User Story:** As a User, I want the platform to deeply understand what I am trying to create before it writes the prompt, so that the enhanced prompt accurately reflects my intent and produces a relevant image.

#### Acceptance Criteria

1. WHEN the User submits a Casual_Prompt, THE Intent_Analyzer SHALL analyze the subject matter, context, mood, and artistic style references before passing any output to the Prompt_Enhancer or Clarification_Engine.
2. THE Intent_Analyzer SHALL extract and structure the following attributes from the Casual_Prompt: primary subject, setting or background, artistic style, mood or tone, and color palette cues; IF an attribute cannot be determined from the Casual_Prompt, THE Intent_Analyzer SHALL mark that attribute as absent rather than omitting it.
3. WHEN Reference_Inputs are provided, THE Intent_Analyzer SHALL augment the structured attribute set derived from the Casual_Prompt with information from those inputs; IF a Reference_Input provides a value for an attribute already extracted from the Casual_Prompt, THE Reference_Input value SHALL take precedence.
4. WHEN the Intent_Analyzer completes its analysis, THE Platform SHALL make the structured attribute record available to both the Clarification_Engine and the Prompt_Enhancer before either component begins processing.
5. IF the Intent_Analyzer cannot determine the primary subject from the Casual_Prompt, THEN THE Platform SHALL halt progression, display an inline message asking the User to describe the primary subject more clearly, and SHALL NOT invoke the Clarification_Engine or Prompt_Enhancer until the User resubmits with a Casual_Prompt from which a primary subject can be extracted.

---

### Requirement 3: Clarifying Questions

**User Story:** As a User, I want the platform to ask me a small number of targeted questions about my intent, so that the final image matches exactly what I have in mind.

#### Acceptance Criteria

1. WHEN the Intent_Analyzer completes its analysis and identifies one or more ambiguities, THE Clarification_Engine SHALL generate between 2 and 3 clarifying questions, each derived from a distinct ambiguity identified in that analysis.
2. WHEN the Intent_Analyzer completes its analysis and identifies no ambiguities, THE Platform SHALL skip the clarification step and proceed directly to the Prompt_Enhancer.
3. WHEN clarifying questions are displayed, THE Platform SHALL prevent invocation of the Prompt_Enhancer until the User has submitted a response to every displayed question.
4. THE Clarification_Engine SHALL present each clarifying question with 3–5 selectable answer options and a free-text "Other" option; the selectable options SHALL be derived from the ambiguity being resolved.
5. IF the User selects the "Other" option for a clarifying question, THEN THE Platform SHALL display a text input accepting between 1 and 200 characters; THE Platform SHALL block submission of that question's response if the "Other" field is empty.
6. THE Clarification_Engine SHALL generate no two questions targeting the same image attribute (for example, it SHALL NOT ask about art style twice).

---

### Requirement 4: Prompt Enhancement

**User Story:** As a User, I want the platform to automatically rewrite my casual description into a detailed, technically correct AI image prompt, so that the image generator produces high-quality, accurate results without my needing to write prompts myself.

#### Acceptance Criteria

1. WHEN the User has answered all clarifying questions (or the clarification step was skipped), THE Prompt_Enhancer SHALL call the Groq API (Llama 3.3 70B model) with the structured intent analysis and clarification answers to produce the Enhanced_Prompt.
2. THE Enhanced_Prompt SHALL be a single, coherent string of between 50 and 500 characters that explicitly covers subject, style, composition, lighting, color palette, and mood.
3. WHEN an existing image is being edited, THE Prompt_Enhancer SHALL receive the Style_DNA of that image as a mandatory input and SHALL reference each Style_DNA attribute (dominant color palette, artistic style label, lighting descriptor, and texture descriptor) within the Enhanced_Prompt.
4. IF the Groq API returns an error or does not respond within 15 seconds, THEN THE API_Routes SHALL retry the request once after a 2-second delay; IF the retry also fails, THEN THE Platform SHALL display an error message and return the User to the clarification step with their previous answers preserved.
5. IF the Groq API response indicates a content policy violation, THEN THE Platform SHALL display a message informing the User that the request cannot be processed due to content restrictions, and SHALL NOT invoke the Image_Generator.

---

### Requirement 5: Prompt Review Step

**User Story:** As a User, I want to see and optionally edit the enhanced prompt before the image is generated, so that I remain in control of what gets created and can correct any misinterpretations.

#### Acceptance Criteria

1. WHEN the Prompt_Enhancer produces the Enhanced_Prompt, THE Platform SHALL display it to the User in an editable text field before any image generation request is made.
2. THE Platform SHALL require the User to explicitly click a clearly labeled "Approve & Generate" button to proceed; image generation SHALL NOT begin without this explicit User action.
3. WHEN the Enhanced_Prompt is displayed for review, THE Platform SHALL display the original Casual_Prompt in a read-only field alongside the Enhanced_Prompt so the User can compare the two.
4. WHEN the User edits the Enhanced_Prompt directly in the review field, THE Platform SHALL use the edited version as the final prompt for image generation, not the original Enhanced_Prompt.
5. WHEN the User clicks a "Regenerate" control (without approving), THE Platform SHALL clear the currently displayed Enhanced_Prompt, re-invoke the Prompt_Enhancer using the same intent analysis and clarification answers, and SHALL disable the "Approve & Generate" button until the new Enhanced_Prompt is fully displayed.
6. WHEN the editable Enhanced_Prompt field reaches 4,000 characters, THE Platform SHALL block further input to that field and display a character-limit indicator; THE Platform SHALL prevent submission of prompts exceeding 4,000 characters.

---

### Requirement 6: Image Generation

**User Story:** As a User, I want the platform to generate a high-quality image from my approved prompt using the appropriate model, so that I receive results suited to my quality and speed expectations.

#### Acceptance Criteria

1. WHEN the User clicks "Approve & Generate", THE Image_Generator SHALL call the Cloudflare Workers AI API with the approved Enhanced_Prompt and the selected generation mode.
2. WHILE the User is reviewing the Enhanced_Prompt, THE Platform SHALL display a generation mode selector with two options: "Fast" (described as "Generates in seconds, good for quick previews") and "Quality" (described as "Takes longer, optimized for detail and accuracy"), with "Fast" selected by default.
3. WHEN the generation mode is "Fast", THE Image_Generator SHALL use the FLUX.1-schnell model.
4. WHEN the generation mode is "Quality", THE Image_Generator SHALL use the FLUX.1-dev model.
5. WHILE image generation is in progress, THE Platform SHALL display a loading indicator; IF generation has not completed within 60 seconds, THE Platform SHALL display a timeout error message and allow the User to retry.
6. WHEN image generation completes successfully, THE Platform SHALL display the generated image in PNG format and store it in the Image_Store with its Enhanced_Prompt and Style_DNA as associated metadata.
7. IF the Cloudflare Workers AI API returns an error, THEN THE Image_Generator SHALL retry the request once after a 2-second delay; IF the retry also fails, THEN THE Platform SHALL display an error message indicating the cause and allow the User to attempt generation again without re-approving the prompt.
8. WHEN image generation completes, THE Platform SHALL append the generated image, its Enhanced_Prompt, and its Style_DNA to the Edit_History for the current Session.

---

### Requirement 7: Style Preservation and Edit History

**User Story:** As a User, I want the platform to remember the visual style of my images across iterative edits, so that subsequent edits remain consistent with the original look and feel rather than drifting to a generic AI aesthetic.

#### Acceptance Criteria

1. WHEN an image is generated, THE Platform SHALL compute and store a Style_DNA object containing: dominant color palette (3–8 colors expressed as hex codes), detected artistic style label, lighting descriptor, and texture descriptor.
2. WHEN the User initiates a new edit on an existing image from the Edit_History, THE Prompt_Enhancer SHALL receive the Style_DNA of that image as a mandatory input and SHALL reference each Style_DNA attribute explicitly within the Enhanced_Prompt.
3. THE Platform SHALL display the Edit_History for the current Session as a visual timeline of thumbnail images in chronological order.
4. WHEN the User selects an image from the Edit_History, THE Platform SHALL restore the Casual_Prompt, Enhanced_Prompt, and Style_DNA associated with that image as the current working context within the same browser session.
5. WHILE a valid Session exists, THE Platform SHALL preserve the Edit_History.
6. IF the Session ends (browser tab is closed), THEN THE Platform SHALL store the Edit_History and associated Image_Store entries so the User can access them upon returning within 24 hours using the same Session identifier.
7. WHEN the Edit_History reaches 50 entries, THE Platform SHALL remove the oldest entry and its associated Image_Store objects to make room for the new entry.

---

### Requirement 8: Inpainting Support

**User Story:** As a User, I want to paint over a specific area of an existing image and describe only that area's change, so that I can make targeted edits without affecting the rest of the image.

#### Acceptance Criteria

1. WHEN the User selects an existing image for editing, THE Platform SHALL offer an "Edit a specific area" option that activates the Inpainting_Tool.
2. WHEN the Inpainting_Tool is active, THE Platform SHALL render the image with a brush tool that allows the User to paint the region they want to change, producing an Inpaint_Mask.
3. THE Platform SHALL allow the User to adjust the brush size of the Inpainting_Tool within a range of 5 to 100 pixels.
4. WHILE the Inpainting_Tool is active, THE Platform SHALL provide a "Clear Mask" button that removes all painted regions from the Inpaint_Mask and resets the canvas to an unmasked state.
5. WHEN the User submits an inpainting request, THE Platform SHALL pass both the original image and the Inpaint_Mask to the Image_Generator along with the approved Enhanced_Prompt.
6. WHEN an inpainting request is submitted, THE Intent_Analyzer SHALL treat the analysis as scoped to the masked region and SHALL extract attributes only for that region.
7. WHEN an inpainting request is submitted, THE Clarification_Engine SHALL generate questions relevant only to the masked area and SHALL NOT ask about aspects of the image outside the mask.
8. WHEN the Prompt_Enhancer processes an inpainting request, THE Enhanced_Prompt SHALL explicitly state that only the masked region is to be changed and that all image content outside the mask is to be preserved unchanged.
9. IF inpainting generation fails after one retry, THEN THE Platform SHALL display an error message and allow the User to resubmit the inpainting request without clearing the Inpaint_Mask or the Casual_Prompt.
10. IF the Inpaint_Mask covers less than 1% of the total image area, THEN THE Platform SHALL display a warning dialog asking the User to confirm before proceeding; IF the User declines, THE Platform SHALL return to the Inpainting_Tool with the existing mask intact.

---

### Requirement 9: Session Management

**User Story:** As a User, I want my work to be preserved within my current session without requiring account creation, so that I can use the platform immediately without friction.

#### Acceptance Criteria

1. WHEN the User first visits the Platform, THE Platform SHALL automatically create a unique Session identifier and associate it with that browser context, without requiring login or account creation.
2. THE Platform SHALL store the Session identifier in the User's browser using a secure, HTTP-only cookie with a 24-hour sliding expiry that resets on each request.
3. WHILE a valid Session exists, THE Platform SHALL restore the User's Edit_History and associated images from the Image_Store upon page reload.
4. IF the Session identifier is absent or expired, THEN THE Platform SHALL create a new Session and present the User with an empty Edit_History and no images loaded.
5. THE Platform SHALL associate all images stored in the Image_Store with the Session identifier so that image retrieval is scoped to that Session.
6. THE Platform SHALL NOT require the User to create an account, provide an email address, or authenticate beyond the automatic Session cookie.
7. WHEN a Session expires, THE Platform SHALL delete all Image_Store entries associated with that Session identifier.

---

### Requirement 10: API Route Orchestration

**User Story:** As a developer, I want the platform's backend logic to be handled by Next.js API routes, so that all LLM and image generation calls are made server-side and API keys are never exposed to the browser.

#### Acceptance Criteria

1. THE API_Routes SHALL handle all calls to the Groq API and Cloudflare Workers AI API server-side, so that API credentials are never transmitted to or accessible from the browser client.
2. THE API_Routes SHALL validate all inputs received from the client before forwarding them to external services; IF validation fails, THEN THE API_Routes SHALL return a 400 status code with an error message identifying the invalid field and the reason for rejection.
3. THE API_Routes SHALL return structured JSON responses to the client for all operations, including success payloads and error details.
4. IF an API_Route encounters an unhandled exception, THEN THE API_Routes SHALL log the error server-side (including request identifier, error type, and timestamp) and return a 500 status code with a generic error message to the client that excludes stack traces, file paths, and environment details.
5. IF a client request payload exceeds 15 MB, THEN THE API_Routes SHALL return a 413 status code with an error message stating the maximum payload size, without forwarding the request to any external service.
6. IF the Groq API or Cloudflare Workers AI API does not respond within 30 seconds, THEN THE API_Routes SHALL abort the request and return a 504 status code with a timeout error message to the client.
